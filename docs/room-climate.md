# Room climate — RoomClimate v1 / heating library 0.3.58

RoomClimate is an independent room-climate module in the Heating-Control library. It displays enabled measured temperature, target temperature and relative-humidity sources grouped by floor and room. Passkey-authenticated page users can change which configured sources are displayed and included in averages. The page does not write thermostat targets, operate heating, change sensor settings or alter archive logging.

## Install and open

1. Update Heating-Control to 0.3.58, build 69, then create a **RoomClimate / Room Climate** instance.
2. Select the **new native SecretsBackend** in `BackendInstanceID`. Automatic selection works when exactly one eligible backend/frontend pair exists. Legacy SecretsManager authentication is not accepted. The backend must expose `SECB_IsNativePortalAuthenticated` and `SECB_GetNativePortalLoginURL`; these are supplied by the native backend's LegacyRuntime integration bridge. No old vault is accessed.
3. Apply changes. Open the child **Room climate page** path `/hook/room_climate_<instanceID>` using the native Secrets HTTPS address. Anonymous access redirects to the new SecretsFrontend passkey login. Primary and approved backup-origin/transport checks are delegated to the native backend. Sessions are checked on every request, including cached history. No custom passkey store or browser token is created.
4. Update **Portal to 1.7** for automatic discovery under **Smart Home → Room climate**. The page offers Portal and Documentation return links. If multiple instances exist, select the intended Portal/Documentation in the module form.
5. Review **Floors, rooms and sources**. All source variables are selected through the object tree. Each room has a stable key, floor and room name, and a list of sources with variable ID, type and readable source name. Add, rename or remove rooms/sources in this graphical editor, then Apply.

The supplied Berlin template has **21 rooms and 88 source mappings**, derived from settings(4).json (10 October 2026) and Produktion.ipsView (9 October). It includes HomeMatic room temperature/humidity, KNX presence-sensor temperatures, Shelly and FRITZ radiator actuals, one associated thermostat target per radiator room and four shared air targets, the explicitly faulty Shelly H&T and identified FRITZ socket thermometers. Shared targets appear in both constituent rooms. Device-mounted thermometer labels distinguish them from reference room sensors. These are mappings, not saved temperature readings. Current values are read locally at request time. Other installations must replace Berlin-specific IDs.

## Source settings — 0.3.58, build 69

Open the **Source settings** tab on the passkey-protected Room climate page. Sources are listed by floor and room, with their type and Symcon variable ID. Switch individual sources on or off and select **Save source settings**. The page searches room, floor and source names; **Reload settings** discards unsaved changes only after the separate discard action. Every user with an authenticated native Secrets application session for this page may change these display selections.

A switched-off source is omitted from current readings, the inactive-sensor list, room averages, target display, room history and 24-hour tile charts. It remains in the configuration and in this tab, and can be turned back on. This does not delete a Symcon variable or archive, modify a device, or change a thermostat setpoint. Selecting a source again does not invent history. The existing one-associated-target rule and HomeMatic target exclusion remain in effect.

By default, where a room has a mapped FRITZ thermostat target, Shelly sources in that room are switched off. The first-floor **master-bathroom** room key is the exception: both Shelly temperature sources 59814 and 52019 remain enabled alongside FRITZ actual temperature 32551 and target 48034. In the supplied Berlin mapping the default exclusions are computer room: Shelly radiator 26654 and the marked-faulty Shelly H&T temperature 53344 and humidity 20226; gym: Shelly radiator 15718; washroom: Shelly radiator 34067; ground-floor guest bathroom: Shelly radiator 23367. Shelly sources in rooms without a mapped FRITZ thermostat, such as the offices and upstairs guest bathroom, stay enabled. All exclusions can be overridden individually.

Defaults are computed from the active FRITZ target and source labels without rewriting saved room mappings, so existing instances and older imports acquire them automatically. A saved on/off choice takes precedence and is tied to the room's stable key and variable ID. A renamed room key may need its selections reviewed. **SourceSettings** is part of the versioned native export and configuration backup; the session-bound CSRF key and native sessions are excluded. Older RoomClimate.v1 imports acquire the default selection, while source-switch backups require RoomClimate 0.3.58 or later. Restore retains the module's existing web-disabled safety behavior.

Settings writes recheck the native Secrets session and trusted HTTPS origin, require a session-bound CSRF token, reject stale revisions and preserve pending console edits. Reads, changes to other views and unchanged live data retain the existing compact polling behavior; the settings list is requested only when its tab is opened. A timed-out save should be checked by reloading settings before retrying.

## One target per room — 0.3.56, build 67

Each room has one associated target. HomeMatic target setpoints are excluded; measured HomeMatic room temperature and humidity remain ordinary sensor inputs. In the Berlin template, FRITZ thermostat targets are used for gym (12312), washroom (35995), computer room (43932) and master bathroom (48034). Shelly targets are used for electronic office (46648), Penny’s office (51537), basement toilet (17850) and upstairs guest bathroom (35786). The ground-floor guest bathroom uses FRITZ target 24196 and actual temperature 52709 (device 24829). Living/dining use shared air target 12594; kitchen/blue room use 37341; master bedroom uses 30481; both guest bedrooms use 40975. The five other rooms have no evidenced target and show that explicitly.

Existing multi-target mappings are normalized when read by the page, history and console editor, and during native export/import. The supplied HomeMatic wall-target IDs and target labels containing HomeMatic are excluded. FRITZ thermostat mappings take precedence over older Shelly mappings; other thermostat/radiator-labelled targets take precedence over shared air targets. Equal-priority entries use the first configured entry. Selection is deterministic: an unavailable selected thermostat does not cause fallback to an older target. To change the target, edit its mapping in the instance form. No controller setpoint or heating device is written by this migration.

The configuration backup envelope retains a source hash of the actual saved properties; its native payload contains normalized mappings. Older RoomClimate.v1 imports remain supported and are normalized before saving. The source-format validator remains a format check, not a live restore test.

## Tile charts, outside conditions and bathroom correction — 0.3.56, build 67

Every summary tile includes a small **24-hour temperature chart**. It plots the arithmetic mean of available hourly recorded means for the room’s currently valid temperature sources. Temperature sources that are presently inactive/missing/invalid are excluded. A historical hour uses only sources with an actual recorded value for that hour, with no interpolation or zero filling. Gaps stay disconnected. Hover or touch the chart for the recorded hour and mean temperature. Mini charts display temperature only; opening the room retains the full source-specific temperature, target and humidity charts. No archived records produces an explicit empty chart; partial archive coverage is labelled.

Tile history loads lazily when a tile approaches the viewport, in batches of at most **four rooms**, with at most **26 hourly records per source**. Replies contain only compact room-average points, not every source history. The browser and server cache each room’s tile history for **five minutes**. Scrolling to a previously loaded tile or switching views reuses its cache. Hidden tabs pause/abort requests, requests never overlap, and failures back off for 30 seconds. All requests and cached replies pass the new native Secrets session and transport checks. Rooms outside the configured allowlist, duplicate room keys and batches larger than four are refused before archive reads. Current tile numbers and weather still use the ordinary two-second changed-value feed; mini charts are historical hourly summaries and refresh separately.

At the top of the page, **Outside temperature** and **Outside humidity** show current values with update times or a stale/unavailable indication. Defaults are Berlin’s **Tempest temperature 17059** and **humidity 38406**. Both are selectable under the instance’s outside-variable fields; clear a selector to disable that reading. These IDs participate in the existing state/delta response, so there is no separate weather polling request. They are included in native configuration exports and Configuration Backup; older v1 imports acquire these defaults.

The user-supplied screenshots confirm **ground-floor guest bathroom FRITZ device 24829**, actual temperature **52709**, target **24196**. The supplied legacy room mapping replaces Shelly target 54714 and adds the FRITZ actual temperature automatically for existing instances and native imports. Different explicit FRITZ target mappings are preserved. **Small first-floor master-bathroom radiator device 19471** was already mapped to actual **32551** and target **48034**; these remain unchanged. Screenshot readings are evidence for IDs, not hard-coded live temperatures.

## Room summary tiles — 0.3.56, build 67

The default **Room summary** view shows one tile per room, grouped by floor. The main number is the arithmetic mean of every valid, enabled current temperature source mapped to the room, with each source counted once. All enabled source types participate, including device-mounted thermometers. Tiles show the average temperature, target values and differences. Source names, IDs, counts, ranges and inactive-sensor counts are omitted from the tile view; full source information remains available in the source views and history charts. Measurements with no update for at least 86,400 seconds, no update recorded, invalid values or missing/unavailable variables are excluded. No qualifying data displays an em dash, never a fabricated zero.

Each room shows at most one **Target**: its associated radiator thermostat setpoint, otherwise its shared air-heating target. HomeMatic wall-thermostat targets are excluded. Rooms without a mapped target show No target configured. For each available target, **Target − average** compares that setpoint with the unrounded measured mean: positive means the target is above the measured average; negative means the room average is above that target. The selected target is not removed just because it has not changed for a day. Missing/invalid targets and differences are explicitly unavailable.

**All active sources** shows current measured values, humidity and every target. **Inactive sensors** groups older/unupdated temperature and humidity sources by floor and room, retaining their last reading and update timestamp. The tab includes a count of inactive room-source mappings. Invalid readings that have updated recently remain identifiable in the active-source view but are excluded from means. A recovered sensor returns to the active view and mean on the next normal delta refresh. Click a room tile or source-view heading to open the same all-source history charts; archived history remains accessible for inactive sensors.

The 24-hour rule is fixed for this overview. The former StaleSeconds property remains accepted in old configuration exports for import/backup compatibility; it is no longer shown in the editor or used to classify readings. Room-average calculations use already-loaded readings in the browser. The small tile-history charts use separately cached, bounded archive requests as described below.

## Reading the page

The three floors are Basement, Ground floor and First floor. Search filters room, floor and source names. Every source shows its variable ID and update timestamp. Missing, invalid, unavailable and stale measurements remain visible with a status. Measured sensors are inactive when no update has arrived for at least 24 hours, or no update has ever been recorded. These move to the separate **Inactive sensors** view. Targets retain their update timestamp and stay visible even when an unchanged setpoint is old. Temperature validity is −50 to 100°C; humidity is 0–100%. No invalid value is converted to zero.

Click any room to open two history plots: measured/target temperatures in °C, and humidity in %. Each source has its own colour; targets are dashed steps. Toggle individual series in the legend. Pointer/touch tooltips show each nearest recorded reading and its actual timestamp, so different sensor sampling times remain visible. Large gaps in measured temperature/humidity are left disconnected. Hovered times are in the browser timezone. This is a recorded-history comparison, not interpolation or an average of multiple sensors.

Choose 1 hour, 6 hours, 24 hours, 7 days or 30 days. Measurements use recorded readings up to 24 hours and hourly means for 7/30 days. Targets use recorded steps, with a labelled carry-in from the last prior archived setpoint when available. The carry-in keeps its original measurement timestamp in tooltips. If a series exceeds 1,000 points, only the latest 1,000 are returned and truncation is explicitly shown; a truncated target series gets no assumed earlier carry-in. Counter archives, absent logging, ambiguous archives and failed/missing APIs are reported separately per source. The module never enables logging automatically; historical data exists only if it was previously recorded.

## Traffic and responsiveness

The first state request includes room/source metadata and current readings. Subsequent requests carry an opaque cursor and return only changed values/status/timestamps. Unchanged responses are typically around 120 bytes of JSON (plus HTTP and native session validation overhead). Default refresh is every two seconds, editable from 1–60 seconds. This is polling, not guaranteed instantaneous push delivery. Timestamp updates count as changes even if the reading is numerically unchanged. No full page is reloaded.

Polling runs only while the tab is visible, uses no overlapping requests, pauses/aborts when hidden, and tolerates up to 90 seconds for a slow request. A restart/configuration change invalidates the cursor and causes a fresh metadata snapshot. History loads only for the opened room, is cached for 30 seconds and refreshes every 60 seconds while the dialog is visible. Closing it stops history requests. A disconnected page retains its last values and displays a connection warning. History requests cannot select arbitrary unmapped variables.

## Debug, import/export and central configuration backup

`DebugEnabled` writes a bounded 32,000-byte **Debug log** string variable below the instance. **Status** reports setup issues; **Room climate page** holds the hook path. No cookies, credentials or session material are logged or exported.

**Export configuration** fills the form's configuration field. **Import configuration** validates the versioned `RoomClimate.v1` document, property types, complete mapping structure and size limits before mutation. Import always disables web access until the native Secrets binding and local IDs are reviewed and the page is enabled again. It does not import current readings, history, debug logs or sessions.

The module implements `RCL_ExportConfigurationBackup` and `RCL_ValidateConfigurationBackup` using the existing **Symcon.ConfigurationBackup.v1** protocol. Current Configuration Backup automatically discovers these module-owned capabilities; no hard-coded adapter or additional source fingerprint approval is needed. Capture includes all configuration properties, verifies sourceHash against saved properties, and runs the native importer-format validator. Native manual restore uses `RCL_ImportConfig(instanceID, payloadJSON)`. A passing format validation is not an executed restore test. Include this instance under Configuration Backup's ordinary instance-selection rules.

## Validation and deployment limits

`php tests/room-climate-source-settings.php` checks source defaults, master-bathroom exception, session-bound writes, chart filtering and backup/restore as well as native-only authentication, failed/expired authentication, origin rejection, protected history cache, state deltas, stale/invalid measurements, duplicate archive timestamps, schema validation, import safety and debug output. `node tests/room-climate-ui.cjs` checks desktop/mobile layout, real CSP, room search, history modal, series toggles and tooltips with synthetic fixture values. Existing heating tests remain required. Live passkey login, archive coverage, actual source mappings and high-latency performance require checking after installation on Symcon.
